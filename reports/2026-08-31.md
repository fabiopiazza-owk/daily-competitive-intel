## 6. Build Signals for K Platform

### 🥇 GxP-grade Agent Evidence Bundles
**Rationale:** The "correlated failure" paper + Optum lawsuit + cross-org accountability arxiv converge on a single message: pharma legal will block agentic K deployments without cryptographically verifiable, offline-auditable agent traces. This is a moat vs. Biomni/OpenAI Health, who are shipping agents without audit primitives. Ship a signed evidence-bundle spec (inputs, tool calls, model versions, guardrail decisions, human overrides) exportable to sponsor QA systems.
**Effort:** 6–8 weeks for MVP (spec + signing + AZ pilot); 1 quarter for full integration into K agent runtime.

### 🥈 Step-Level Guardrails for Clinical Tool Calls
**Rationale:** StepGuard + DDI-under-uncertainty papers show pre-execution monitoring is now table stakes. K agents that touch clinical data, protocol amendments, or safety databases need per-step policy checks with calibrated abstention, not post-hoc review. Directly de-risks Sanofi expansion into pharmacovigilance workflows.
**Effort:** 4–6 weeks; leverage existing K policy engine, add step-level hook + calibrated confidence gating.

### 🥉 Multilingual Prompt Compression Benchmark for K
**Rationale:** Cross-lingual audit shows extractive compressors degrade unevenly across languages, and non-English content already costs 1.3–1.8× more tokens. For Sanofi (FR/DE/JP sites) and AZ (global trials), uncontrolled compression = silent quality regression + cost overruns. Build an internal benchmark + per-language compression policy before we scale multilingual deployments.
**Effort:** 3 weeks (benchmark harness + policy config); ongoing per-language calibration.
